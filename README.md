# deno-manifest-action

Generate `package.json` or `jsr.json` from a repository `deno.json`.

This action:

- reads `deno.json` from the root of the calling repository
- runs the generator script with `--type=...`
- writes the generated manifest to the file you choose

## Usage

```yaml
name: Generate package manifest

on:
  workflow_dispatch:

jobs:
  generate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: denoland/setup-deno@v2
        with:
          deno-version: v2.x

      - uses: quentinadam/deno-manifest-action@v1
        with:
          type: npm
          output_file: package.json
```

## Inputs

| Name          | Required | Description                                                                             |
| ------------- | -------- | --------------------------------------------------------------------------------------- |
| `type`        | yes      | Target manifest type: `npm` or `jsr`                                                    |
| `output_file` | yes      | Output file path relative to repository root (for example `package.json` or `jsr.json`) |

## Dependency Analysis

The generator does not blindly copy all dependencies from `deno.json`. It computes the dependencies that are effectively
used by your public API:

- It collects all paths declared in `exports`.
- For each exported path, it runs `deno info --json <path>` to get the module graph.
- It recursively traverses the graph and records only package imports (`jsr:` or `npm:`) that are actually referenced.
- It resolves those package aliases through `deno.json#imports` and keeps only the used packages in the generated
  manifest.

Result:

- `type: npm` generates a `dependencies` object with only used packages and versions.
- `type: jsr` generates an `imports` object with only used package mappings.

## Manifest Field Mapping

### `type: jsr`

Copied from `deno.json`:

- `name`
- `version`
- `license`
- `exports` (copied as-is)

Generated by the script:

- `publish` is always set to:
  - `include: ["src", "README.md"]`
  - `exclude: ["**/*.test.ts"]`
- `imports` contains only effectively used dependencies discovered from the export graph

### `type: npm`

Copied from `deno.json`:

- `name`
- `version`
- `description`
- `license`
- `author` (if present)
- `repository` (if present)

Generated/transformed by the script:

- `type` is always `"module"`
- `files` is always `["dist", "README.md"]`
- `exports` is transformed for npm build output:
  - leading `./src/` becomes `./dist/`
  - trailing `.ts` becomes `.js`
- `dependencies` contains only effectively used dependencies discovered from the export graph

## Examples

Generate `package.json`:

```yaml
- uses: quentinadam/deno-manifest-action@v1
  with:
    type: npm
    output_file: package.json
```

Generate `jsr.json`:

```yaml
- uses: quentinadam/deno-manifest-action@v1
  with:
    type: jsr
    output_file: jsr.json
```

## Notes

- The action expects `deno.json` to exist at the repository root.
- The generated `output_file` is written relative to the repository root.
